## ADDED Requirements

### Requirement: 月度汇总与逐项明细
系统 SHALL 为每个经营月份保存唯一的汇总快照，并保存组成该快照的每个收入和成本项目明细。

#### Scenario: 生成月度快照
- **WHEN** 系统为一个尚未锁账的月份生成快照
- **THEN** 系统在同一事务中保存汇总与全部逐项明细，且汇总金额等于明细聚合结果

### Requirement: 月份唯一与幂等锁账
系统 MUST 保证同一月份最多存在一个有效快照，重复执行自动锁账或手动锁账不得产生重复记录。

#### Scenario: 重复关闭同一月份
- **WHEN** 同一月份的 close 操作被重复调用
- **THEN** 系统返回既有锁账结果且快照和明细数量不增加

### Requirement: 历史不可变
系统 MUST 在月份锁账后保留当时的名称、金额、币种、汇率、到期日和计入原因，后续来源数据变化不得改变已锁账结果。

#### Scenario: 锁账后客户续费
- **WHEN** 历史月份锁账后管理员延长对应 API Key 或客户订阅到期日
- **THEN** 历史月份的有效客户数、收入和明细保持不变

#### Scenario: 锁账后修改汇率
- **WHEN** 管理员修改当前配置中的某月汇率
- **THEN** 已锁账快照继续使用其明细中保存的原汇率

### Requirement: 自动月末锁账与补跑
系统 SHALL 按 `Asia/Shanghai` 在每月1日幂等生成上月实际快照，并提供管理员手动补跑入口。

#### Scenario: 自动任务成功
- **WHEN** 北京时间进入新月份且上月尚未锁账
- **THEN** 后台任务生成并锁定上月快照

#### Scenario: 自动任务失败后补跑
- **WHEN** 自动任务失败且管理员稍后手动关闭该月份
- **THEN** 系统完成同样的校验和幂等写入并清除历史缺口提示

### Requirement: 数据质量标记
系统 MUST 将快照标记为 actual、estimated 或 manual，并在页面中清晰展示；上线前回填不得标记为 actual。

#### Scenario: 估算回填
- **WHEN** 管理员根据当前可见的创建/到期字段回填上线前月份
- **THEN** 系统将快照标记为 estimated 并在月份明细中显示估算提示

#### Scenario: 人工修正
- **WHEN** 管理员录入经确认的历史汇总或明细修正
- **THEN** 系统将数据质量标记为 manual 并保存修改说明和操作时间

### Requirement: 当前月份不提前锁账
系统 SHALL 实时计算当前月份，并 MUST 拒绝在该自然月结束前将其标记为 actual 锁账。

#### Scenario: 尝试提前关闭当前月
- **WHEN** 管理员对当前月份执行 actual close
- **THEN** 系统拒绝操作并继续返回实时汇总
